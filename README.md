# tg-chat-videos

Каталог видео с кавер-гигов The Jammers из чата «Музыканты Кипра».

Сетлисты и даты концертов берутся с https://thejammers.org/archive, видео —
из телеграм-чата. Каждое видео привязывается к концерту по дате (окно от
концерта до следующего) и, если подпись разбирается, к песне из сетлиста этого
концерта. Что не разобралось — лежит в «подвале» концерта, и любой может
привязать это руками через веб-интерфейс, без авторизации. Всё в SQLite.

## Установка

Нужен Python 3.9+ (на Windows проверено с 3.12).

```bash
python -m venv .venv-win
.venv-win/Scripts/python -m pip install -r requirements.txt
cp .env.example .env      # TG_API_ID / TG_API_HASH с my.telegram.org, TG_CHANNEL — чат
```

На Linux вместо `.venv-win/Scripts/python` будет `.venv/bin/python`.

Чат читается пользовательской MTProto-сессией (Telethon): Bot API прошлые
сообщения не отдаёт. Первый раз — `login`, он спросит номер и код и положит
сессию в `tgchannel.session`. Проект только читает чат: `get_entity`,
`iter_messages`, `get_messages` — ничего не пишет и не удаляет.

## Команды

```bash
.venv-win/Scripts/python -m tgchannel login       # разовый вход
.venv-win/Scripts/python -m tgchannel concerts    # концерты + сетлисты с сайта
.venv-win/Scripts/python -m tgchannel fetch       # видео из чата
.venv-win/Scripts/python -m tgchannel match       # привязка к концертам и песням
.venv-win/Scripts/python -m tgchannel serve       # веб-каталог на http://127.0.0.1:8080
```

| Команда | Что делает |
|---|---|
| `concerts [--force] [--reparse]` | список с `/archive`, сетлист каждого концерта из RSC-payload страницы `/events/<id>`; повторный запуск берёт только новые концерты, `--force` — все, `--reparse` — пересобрать из сохранённого JSON без сайта |
| `fetch [--limit N] [--full]` | сообщения с видео (серверный фильтр, текст чата не качается), начиная с даты первого концерта; докачивает новые с `meta.last_video_msg_id`; для видео-ответов подтягивает текст исходного сообщения |
| `match` | окно концерта → `videos.concert_id`; песня — по подписи, подписям соседей по альбому, тексту ответа |
| `all [--limit N]` | concerts + fetch + match |
| `serve [--host H] [--port P]` | каталог с поиском/сортировкой, страницы концертов, подвал и правка |
| `stats` | сводка |

## Как привязывается песня

Сравнение по токенам, нечёткое (`difflib`), чтобы «Disturbed- Down With a
Sickness» находил «Down with the Sickness». Правила в `tgchannel/match.py`:

* `ok` — совпало название (со скобками в названии не считаемся) и исполнитель,
  либо название из двух и более слов / одного длинного слова; подпись вида
  «10 - Ghost» проверяется по позиции в сетлисте;
* `maybe` — только исполнитель, у которого в этом сетлисте ровно одна песня,
  и видео выложено в первые `NEAR_DAYS` (7) дней — позже это уже анонсы;
* иначе видео в подвале, если оно из первых 7 дней; более поздние
  непривязанные не показываются (джемы, чужие клипы).

Видео с концерта выкладывают в ночь концерта и на следующий день — на них
приходится больше половины всех видео чата, и подписи у большинства нет.
Отсюда подвал: там лежит основная масса, и её разбирают руками.

## Веб-каталог

* `/` — таблица «концерт · исполнитель · песня · видео», поиск по любому из трёх,
  сортировка по заголовкам;
* `/concerts` — концерты с числом песен, песен с видео и размером подвала;
* `/concert/<id>` — сетлист с видео под каждой песней и подвал. Метка
  неопознанного видео: `31.10.25 <= 02.11.25 - 1` — дата концерта, дата
  публикации, номер за этот день;
* у каждого видео `⋯` — привязать к песне, пометить «не с концерта», сбросить.

Ручные привязки лежат в `matches` с `confidence = manual`, скрытые видео —
`videos.hidden = 1`; перепрогон `match` их не трогает.

Для сервера: `serve --host 0.0.0.0` за nginx или любым WSGI (`tgchannel.web:app`).
Авторизации нет намеренно — правит чат.

## База

`tg_chat_videos.db` рядом с проектом (или `TG_DB`), схема в `schema.sql`:

* `concerts` — концерты с сайта, `raw_json` — треки как отдал сайт;
* `setlist` — песни концерта по порядку, `ready` = состав собран;
* `videos` — сообщения с видео: подпись, ссылка, альбом, ответ, длительность,
  `concert_id`, `hidden`;
* `matches` — видео ↔ песня, `confidence` = `ok | maybe | manual`;
* `meta` — id чата, `last_video_msg_id`.

Участники составов в базу не пишутся — каталогу нужны только песня и дата.

## Деплой на Ubuntu (nginx + systemd, от root)

```bash
# на сервере
git clone <repo> /opt/tg-chat-videos
# с рабочей машины: scp .env tgchannel.session tg_chat_videos.db root@server:/opt/tg-chat-videos/
bash /opt/tg-chat-videos/deploy/install.sh videos.example.com 8090   # второй параметр — порт gunicorn, если 8080 занят
certbot --nginx -d videos.example.com
```

`deploy/install.sh` ставит venv с gunicorn, `tg-chat-videos.service`
(gunicorn на 127.0.0.1:8080), `tg-chat-videos-sync.timer` (раз в час
`python -m tgchannel all`: новые концерты, новые видео, перепривязка) и
сайт nginx с указанным доменом. Базу можно не копировать — тогда первый
запуск `all` скачает всё сам (пара минут).

Обновление кода: `bash deploy/push.sh [root@host]` — rsync без базы, сессии и `.env`
плюс рестарт сервиса. Базу на сервер копировать только один раз, при первой
установке: в ней живут ручные правки из чата, и локальная копия их затрёт.
