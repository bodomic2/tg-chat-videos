# tg-channel-log

Выкачивает историю телеграм-канала, разбирает посты вида
**«Исполнитель - Название (примечания)»** в первой жирной строке, складывает всё
в SQLite и генерирует каталог: исполнители → песни → даты постов.
Повторные исполнения одной песни собираются в одну строку с несколькими датами.

## Почему не бот-токен

Bot API не отдаёт прошлые сообщения канала — бот видит только то, что приходит
после его добавления. Поэтому история качается пользовательской MTProto-сессией
(Telethon): `api_id` + `api_hash` с https://my.telegram.org → API development tools,
затем разовый вход по номеру телефона. Сессия ложится в `tgchannel.session`
рядом с проектом, второй раз код запрашивать не будет.

## Установка

Проект живёт на Windows-диске, а запускается из WSL
(`/mnt/c/Users/bodom/Documents/git/tg-channel-log`).

В Ubuntu 26.04 модуль venv идёт отдельным пакетом, поэтому один раз:

```bash
sudo apt install -y python3-venv
```

Дальше:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env      # и заполнить TG_API_ID / TG_API_HASH / TG_CHANNEL
```

`TG_CHANNEL` — `@username`, ссылка `https://t.me/username` или числовой `-100…` id
приватного канала (на него нужно быть подписанным тем же аккаунтом).

## Запуск

Всё запускается интерпретатором из `.venv` — активировать окружение необязательно:

```bash
.venv/bin/python -m tgchannel fetch --limit 200
.venv/bin/python -m tgchannel parse --dry-run
.venv/bin/python -m tgchannel all
```

Либо один раз `source .venv/bin/activate` — и дальше просто `python -m tgchannel …`.

| Команда | Что делает |
|---|---|
| `fetch [--limit N] [--full]` | качает посты в таблицу `messages`; по умолчанию только новые (с `meta.last_msg_id`), `--full` — заново с начала |
| `parse [--dry-run] [--sample 30] [--status ok\|maybe\|other]` | пересобирает `tracks`/`appearances` из уже скачанных постов |
| `catalog [--with-maybe]` | пишет `out/CATALOG.md` и `out/catalog.html` |
| `export [--format txt\|json] [--out FILE] [--no-dates] [--with-maybe]` | список распознанных песен в stdout или файл |
| `all` | fetch + parse + catalog |
| `stats` | сводка по базе |

Разбор всегда идёт по сохранённым постам, так что правила в `tgchannel/parse.py`
можно править и прогонять `parse` + `catalog` сколько угодно — канал заново не качается.

## Правила разбора

Каждый пост попадает ровно в одну корзину, и они не смешиваются:

| Статус | Что это | Куда идёт |
|---|---|---|
| `ok` | шаблон: **жирная** первая строка + `Исполнитель - Название (примечания)` | каталог |
| `maybe` | разбирается как песня, но шаблон нарушен (не жирным / кривой разделитель) | отдельный раздел «Похоже на песню» |
| `other` | обычный пост: заметка, ссылка, анонс | отдельный раздел «Прочие посты» |

Как разбирается заголовок:

1. Заголовок — первая непустая строка; «жирная» = покрыта bold-энтити хотя бы на 60%.
2. С начала строки снимаются эмодзи, маркеры, `#хэштеги` и нумерация вида `12.`.
3. Хвостовые `(…)` и `[…]` уходят в примечания.
4. Исполнитель и название делятся по первому ` — `, ` – `, ` -- `, ` - `.
   Дефис **внутри слова** (`что-то`, `sing-recording`) разделителем не считается —
   иначе обычный текст рвётся посреди фразы. Односторонний дефис (`Artist- Title`)
   допускается, но пост уходит в `maybe`.
5. Не жирные заголовки проходят строгий фильтр, чтобы заметка с тире в предложении
   не притворялась песней: не длиннее 100 символов, без ссылок, имя исполнителя
   короче 40 символов и без запятых, исполнитель и название начинаются с заглавной
   буквы или цифры, название не длиннее 9 слов. Не прошло — `other`.
6. Группировка по нормализованному ключу: регистр, кавычки, `ё`/`е`, лишние пробелы,
   ведущее `The`. `DEEP PURPLE  -  Smoke on the Water` и
   `Deep Purple - Smoke on the Water` — одна песня, два исполнения.

Посмотреть, что попало в конкретную корзину, не трогая базу:

```bash
.venv/bin/python -m tgchannel parse --dry-run --status maybe --sample 50
```

## База

`tg_channel_log.db` рядом с проектом (или путь из `TG_DB`):

* `messages` — сырые посты: текст, форматирование, ссылка, статус разбора;
* `tracks` — уникальные пары исполнитель/название;
* `appearances` — по строке на каждое упоминание песни в канале (это и есть повторы);
* `meta` — id и username канала, `last_msg_id` для докачки.

## Каталог

* `out/CATALOG.md` — раздел «Каталог» (исполнители по алфавиту: латиница, потом
  кириллица; песни с датами-ссылками и пометкой `×N` для повторов), затем
  «Похоже на песню» и «Прочие посты» отдельными разделами.
* `out/catalog.html` — то же самое одним самодостаточным файлом: поиск и сортировка
  работают по каталогу, две другие корзины лежат ниже в свёрнутых блоках.
  Внешних зависимостей нет, тема светлая/тёмная по системной.

В каталог входят только песни, подтверждённые хотя бы одним постом по шаблону.
`catalog --with-maybe` добавляет к ним даты из «похожих» постов про уже известные
песни — такие даты помечаются вопросительным знаком (`2025-11-23?`).

Наружу выводятся только метаданные — исполнитель, название, примечания, даты
и ссылки на посты. Тексты постов остаются в базе.

## Простой список песен

`export` даёт только успешно распознанные песни (корзина `ok`), по строке на песню,
в stdout — чтобы можно было грепать и пайпить:

```bash
.venv/bin/python -m tgchannel export                      # Исполнитель - Название (примечания) — даты ×N
.venv/bin/python -m tgchannel export --no-dates           # только «Исполнитель - Название»
.venv/bin/python -m tgchannel export --format json        # массив объектов с датами и ссылками
.venv/bin/python -m tgchannel export --format json --out out/songs.json
```

В JSON у каждой песни: `artist`, `title`, `notes`, `count`, `dates[]`, `links[]`.
Порядок тот же, что в каталоге: латиница, потом кириллица.
